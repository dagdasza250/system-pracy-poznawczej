# SPP v0.5.1 — R2.2 Cardinality & Integrity Contract
## R2.2-B po Review Gate

**Etap:** `R2.2-B`  
**Wersja:** `1.0-rc1`  
**Status:** `READY_FOR_SIGNOFF`  
**Input:** `R2.2-A — Relation Inventory · CLOSED/FROZEN`  
**Baseline modified:** `NO`

## 1. Cel

Zamrozić strukturalne kardynalności, ownership i reguły integralności dla 27 relacji dopuszczonych przez frozen R2.2-A.

R2.2 nie rozstrzyga jeszcze semantycznych wymagań provenance, statusu epistemicznego, confidence ani lifecycle.

## 2. Reguły globalne

1. **`required` nie oznacza automatycznie `minItems ≥ 1`.** Wymagalność pola i liczność relacji są osobnymi własnościami.
2. **Canonical IDs są globalnie unikalne w jednym stanie SPP** dla Source, Segment, Episode, Case, Fragment, Unit, Relation, Hypothesis, Model, Action, Result i ModelVersion-record.
3. **Obiekty analityczne są Case-local.** Fragment, Unit, Relation, Hypothesis, Model, Action, Result i ModelVersion-record mają jednego owning Case i nie mogą być wskazywane cross-Case.
4. **Referencja musi się rozwiązać.** Brak targetu = invalid relation state.
5. **Duplikaty tego samego ID w jednej liście referencji są zabronione.**
6. **Destructive delete obiektu będącego targetem aktywnej referencji jest zabronione.** Archive/supersede należy do R2.6.
7. **Schema enforcement jest przeważnie częściowe.** `$ref: id` sprawdza kształt stringa, nie istnienie targetu ani integralność między polami.
8. **Semantyczne minima provenance są odroczone do R2.5.** Dlatego np. `Unit.fragmentIds` i `Hypothesis.support` mogą mieć strukturalne minimum `0`, mimo że R2.5 może później wymagać źródła dla konkretnych typów treści.

## 3. Rozstrzygnięcia Review B01–B04

### B01 — Case.sourceIds

**DECISION: `SUPERSET_ALLOWED`**

Warunek:

`episodeSourceIds(Case.episodeIds) ⊆ Case.sourceIds`

Każde źródło Episode należącego do Case musi być w `Case.sourceIds`, ale Case może dodatkowo wskazywać Source jeszcze niewykorzystany przez żaden Case Episode.

### B02 — Relation self-loop

**DECISION: `SELF_LOOP_PROHIBITED`**

`Relation.from != Relation.to`

Self-loop nie wnosi użytecznej informacji dla katalogu relacji v0.5.1. Cykle długości > 1 nie są automatycznie błędne. Identyczny triple `(from,type,to)` nie może wystąpić dwukrotnie w tej samej Case.

### B03 — unikalność ID

**DECISION: `GLOBAL_STATE_UNIQUE`**

Każdy kanoniczny entity ID jest unikalny w obrębie całego eksportowanego stanu SPP, nie tylko w obrębie typu lub Case.

JSON Schema tego nie egzekwuje; jest to reguła integralności R2.2.

### B04 — Action ↔ Result source of truth

**DECISION: `RESULT_ACTION_ID_SOURCE_OF_TRUTH`**

- `Result.actionId` = kanoniczna referencja właścicielska;
- `Action.resultIds[]` = opcjonalny zdenormalizowany reverse index;
- jeśli `Action.resultIds[]` istnieje, musi być dokładnie zgodny ze zbiorem Result w tej samej Case, dla których `Result.actionId == Action.id`.

## 5. Reguły integralności szczegółowej

- Episode Segment musi należeć do jego `sourceId`.
- `Case.episodeIds` może wskazywać tylko istniejące Episode, a ich `sourceId` musi należeć do `Case.sourceIds`.
- Fragment może wskazywać tylko Episode należący do owning Case.
- Fragment Segment musi należeć do wskazanego Episode.
- Unit→Fragment, Hypothesis→Unit, Model→Hypothesis/Unit, Action→Model i Result→Action muszą pozostawać w tej samej Case.
- Relation endpointy są Unit-only, w tej samej Case, bez self-loop i bez identycznych duplikatów krawędzi.
- `Action.caseId` nie jest source of truth.
- `Action.resultIds` nie jest source of truth.
- ModelVersion-record ma dokładnie jeden target Model, ale formalne typowanie rekordu pozostaje `SCHEMA_GAP`.
- bezpośrednia relacja Result→ModelVersion nie istnieje w R2.2; trigger wersjonowania należy do R2.6.

## 6. Boundary z późniejszymi etapami

R2.2 nie ustala:
- dla których typów Unit Fragment jest semantycznie obowiązkowy — R2.5;
- minimalnego dowodu dla Hypothesis — R2.5;
- semantyki `contextBeforeIds/contextAfterIds` — R2.5/R2.7;
- archive/supersede i pełnego lifecycle — R2.6;
- sposobu naprawy luk schema — R2.7;
- epistemic status — R2.3;
- confidence — R2.4.
